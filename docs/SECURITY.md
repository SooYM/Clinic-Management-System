# Security boundaries and operating requirements

Sessions use opaque random tokens. Only token hashes persist in MySQL. HTTP-only, SameSite cookies reduce browser exposure; production requires secure cookies over HTTPS. Session expiry and active-user checks run on requests. Independent branch membership and server-enforced role module grants gate application operations. Grants are refreshed on requests; ADMIN always retains all modules. Chart creation/signing and document issuance remain DOCTOR-only; patient medication-taking reports also permit NURSE with clinical access. Incremental numeric identifiers never grant access by themselves. State-changing authenticated calls require matching CSRF token. Login must validate request origin and throttle password attempts.

Passwords use asynchronous scrypt with random 16-byte salts and parameters N=131072, r=8, p=1. Passwords and session secrets must never enter audit logs. [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Clinical and financial requests must validate identifiers, lengths, dates, safe integer quantities and ownership before committing writes. Parameterized SQL prevents value interpolation. Database conflicts must return useful client errors without exposing SQL, stack traces or credentials. [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [OWASP CSRF protection](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

Public displays use ticket numbers and room labels only. Certificate verification uses unguessable tokens and a narrow response; redacted diagnosis must stay absent from public API and public PDF. Clinical PDFs require staff authentication. Revocation must be checked at verification time. Notification recipients require consent, and provider logs must omit unnecessary clinical content.

Recorded allergy matching blocks known text matches; it is not a drug interaction knowledge base. Clinicians must review medication classes, cross-reactivity and incomplete allergy records. Invoice checkout records declared cash/card/QR tender; it does not prove external bank settlement. Ordinary GP invoices generate no commission ledger.

Clinical document preview and PDF reads validate the signing HMAC and snapshot metadata before rendering; changed content is rejected. The preview exposes a redacted display projection, not signing secrets. Diagnosis withholding applies to both outputs.

Patient medication-taking records require clinical module access. Only DOCTOR or NURSE may append a report against a signed prescription; ADMIN can read with clinical access but cannot record a dose. Source distinguishes patient report from staff observation. Branch checks, strict quantities/timestamps, audit and scoped retry keys protect entries. Inventory-only readers retain dispensing activity access without patient-taking reports. Recording a patient dose never changes inventory.

Before live patient use: provision least-privilege database roles, encrypted backups, TLS, secret rotation, monitoring, recovery drills and clinic retention policy. Validate restore, unauthorized role operations and branch isolation in deployment. An application audit ledger supports accountability but is not tamper-proof against database administrators.

Package, commission/policy/payroll and photo endpoints return 410 FEATURE_RETIRED in the deployed GP application. Retained historical photo code requires recorded consent and image signature/size checks, uses AES-256-GCM and binds scope into authenticated additional data. Historical adapter tests run only in an isolated test harness. Keep original keys for retained encrypted data and numeric migration recovery; retired features do not justify deleting keys. Encrypted storage does not sanitize EXIF metadata.

Version 2 publication review scanned source, configuration and documentation while excluding private environment files, local database/backup/browser artifacts, dependencies and build output. No credential-token or private-key candidates were found in the reviewed release source. Environment examples contain placeholders; CI credentials are disposable service-only values; test keys are synthetic. This is a bounded source review, not a guarantee about repository history or hosting configuration. Private `.env` files, `.local` databases/backups and browser artifacts must remain excluded from publication.

Numeric migration is a maintenance operation: verify backups and original keys, stop API/workers, preflight signed records and relationships, then convert. Historical document snapshots are re-signed after typed-reference conversion; photos are re-encrypted with numeric scope. Existing sessions are invalidated. MySQL DDL cannot roll back an interrupted upgrade; restore the pre-upgrade backup.

The free Render build is a separate browser-session simulation with public fictional accounts and an intentionally public demo password. It has no clinical backend, database, real authentication, signed certificates, PDF generation or notification delivery. Browser checks illustrate workflows and can be changed by the browser user; they are not a security boundary. Enter only fictional data. The static transport rejects every `/api` request with 503 and labels unavailable integrations. Local/production MySQL mode retains the authenticated server boundaries described above and does not preload demo fixtures.

Final staged source review covered 121 release source files and all tracked paths. Private environment, local database/backup, dependency/build and browser artifacts were excluded; no secret-token/private-key or personal workstation-path candidates were found. The generated schema reference contains no row data or current sequence counters. This review does not certify historical commits or hosted configuration.

Catalog mutations require ADMIN authorization, branch membership and CSRF. Optimistic versions reject stale edits. Archived choices cannot enter new configured clinical selections. Historical prescriptions remain immutable; existing dispensing stays available. Server-owned medication snapshots ignore untrusted client labels. Inventory category, unit and ingredient cannot change after use.
